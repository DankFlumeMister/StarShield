| 座子 X 向位置 | **板宽方向居中** | marbastlib（USB 注释块 −3.55…+3.55）+ nRF52840-promicro 逆向件（X 居中）⇒ 双旁证 |

### 2.4 天线（顺手核对，不阻塞投板）

marbastlib 在封装里画了一块 `ANT` keepout：**天线在 USB 的对侧（pin 12/24 端）**，
沿板长方向伸出板边约 5 mm、横向超出板宽约 ±5 mm。
⇒ 插到我们板上后，天线区大致覆盖键盘板 **x ≈ 50–60 mm、y ≈ 0–26 mm**（模块中线 y=12）。
该区域下方是我们 In1（GND 平面）/ In2（VLED 平面）/ B.Cu（GND 铺铜）——
「是否给天线挖空铺铜」属旁证级建议、无强规范 ⇒ 记为 **B6 之后的决策项**，量测时顺手记下天线实际位置即可。

## 4. 预判：模块插上我们板后的 USB 落点（拿货后按实测替换）

我们板上 J3A / J3B（`PinSocket_1x12`，rot=90）实测坐标（解析 `Starshield.kicad_pcb`）：

- J3A（PM1–12）：pin1 世界坐标 **(40, 4.38)**，pin12 **(67.94, 4.38)** —— 针位沿 X 向
- J3B（PM13–24）：pin1 **(40, 19.62)**，pin12 **(67.94, 19.62)** —— 两列间距 15.24 ✅
- 模块中线 **y = 12.0 mm**（距键盘板上边缘 12 mm）

按 §2.3 预判（USB 在 pin1 端、X 居中、口面伸出 1.5 mm）：

| 预判量 | 值（键盘板坐标系，原点=板左上角） |
| --- | --- |
| 模块 USB 侧板边位置 | **x ≈ 36.2 mm** |
| **USB 座口面** | **x ≈ 34.7 mm，y ≈ 12 ± 3.6 mm，朝 −X（键盘左侧）** |

⚠️ **由此浮出一个必须正视的机械问题**：座口距键盘板左边缘约 34.7 mm。
「底壳侧壁开孔」方案（`power-architecture.md` §4）下，插线时要横穿这 34.7 mm 的壳内空间
—— **常见 USB-C 插头 tip→线缆段约 30–45 mm，能不能隔着壳壁插到位是临界情况**。
量测当天请**用实物 + 一条普通数据线**实际比划（模拟壳壁挡板），并把结论记回
`power-architecture.md` §4。若不可行，备选：外壳在 USB 口上方开**底壳开槽**（备选方案②）、
或下一代板把 J3A/J3B 旋转 90°（USB 朝上边沿，代价是控制肩重新布件）。
**在核实之前，不要把「侧壁开孔」当成已定事实写进外壳模型。**

## 6. 量测结论（2026-09-19，实物到货当日）

### 6.1 已确认的实测值

| 项 | 实测 | 与预判对比 |
| --- | --- | --- |
| 板长 | **34.0 mm** | 取 34.0/34.1 一侧 ✅（marbastlib 的 33.02 系 Pro Micro 兼容子集，偏小） |
| 板宽 | **18.0 mm** | 取 18.3/17.8 之间 ✅ |
| pin1 → USB 口面 | **5.3 mm** | 与 marbastlib 预判 5.3 **完全一致** ✅ |
| USB 座口宽 | **7.1 mm，板宽居中** | 与预判一致 ✅ |
| 总高 | **3.3 mm** | 预判 3.2–3.3 ✅ |
| **每边孔数** | **13** | ❌ **预判 12 错误**（旁证双重误导：marbastlib 封装与零售商都按 Pro Micro 2×12 抄） |

### 6.2 🔴 发现的设计错误：J3A/J3B 必须从 1×12 改为 1×13

官方 pinout（nicekeyboards.com 原图，本机留档 `.workbuddy/scratch/pinout-v2-a6d36.png`）
确认 nice!nano v2 = **2×13 = 26 孔**，比 Pro Micro 每排多 1 孔——**多在 USB 端**：
左排顶端多 1 个 GND、右排顶端多 1 个 B+（故右排 B+ 有两个孔）。
这也解释了板长 34.0 ≠ Pro Micro 33.02。
（21 GPIO 口径不变：主排针 18 个 D 脚 + 背面 3 个焊盘 P1.01/P1.02/P1.07。）

**对现设计的影响**（`control_design.py` 的映射逐孔对照官方顺序）：

- 左排：我们的 J3A.1（LED_DIN = D1/P0.06）会插到实物的 **GND 孔**上 —— **整排错位一孔**；
- 右排：J3B.1（OUT→RAW/B+）恰好对上 B+ #1（侥幸），但 J3B.4（VCC）会插到实物的
  **RESET 孔**上 —— **VCC 短接复位，致命**；
- **固件 overlay 无需改动**：所有 D 编号（D2/D14/D18 模式、D19/D15/D16 五95、D4–D9 行、
  D1 RGB 数据、D10 门控）与 ZMK gpio-map 的对应关系不变，变的只是物理孔位。

**修正后的插座映射**（新 J3A/J3B = 1×13，编号 = 实物孔位序号，自 USB 端起）：

| J3A（左排） | 网 | | J3B（右排） | 网 |
| --- | --- | --- | --- | --- |
| 1 | GND | | 1 | OUT（B+ #1） |
| 2 | LED_DIN（D1/P0.06） | | 2 | OUT（B+ #2，同网冗余） |
| 3 | NC（D0/P0.08） | | 3 | GND |
| 4 | GND | | 4 | NC（RESET） |
| 5 | GND | | 5 | VCC（3.3V） |
| 6 | MODE0（D2/P0.17） | | 6 | NC（D21，ADC 保留） |
| 7 | NC（D3/P0.20） | | 7 | NC（D20，ADC 保留） |
| 8 | ROW0（D4/P0.22） | | 8 | 595_RCLK（D19/P0.02） |
| 9 | ROW1（D5/P0.24） | | 9 | MODE2（D18/P1.15） |
| 10 | ROW2（D6/P1.00） | | 10 | 595_SCK（D15/P1.13） |
| 11 | ROW3（D7/P0.11） | | 11 | MODE1（D14/P1.11） |
| 12 | ROW5（D8/P1.04） | | 12 | 595_MOSI（D16/P0.10） |
| 13 | ROW4（D9/P1.06） | | 13 | RGB_PWR_EN（D10/P0.09） |

### 6.3 修复方案（待执行）

1. **原理图链**（安全，走既有流水线）：`control_design.py` 改 Conn_01x12 → Conn_01x13、
   按上表重排 net-map → `gen_control_sch.py` → `verify_control.py`（断言里的孔号同步改）。
2. **PCB 手术**（⚠️ 不能跑 `gen_pcb.py`，会覆盖布线）：J3A/J3B 封装换 1×13、
   平移使**远端孔（13）与旧孔 12 位置重合**（这样靠近远端的走线基本不动，
   只有近 USB 端的 fan-out 需要 2.54 mm 平移重接）→ 局部改线 → `refill_zones.py` 重填 → DRC。
   注意：新孔 1 会比旧孔 1 再向 USB 口靠近 2.54 mm（x≈37.5），与座口（x≈34.7）仍有 ~2.8 mm 空隙。
3. **文档**：`controller-and-battery-facts.md` §1.1、handoff §8/§9.1、`bq24072-pinout.md`/
   `power-architecture.md` 中提及 RAW 的孔号处（改完按「位号 + 孔号」grep）。
