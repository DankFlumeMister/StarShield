## 1. 结论速览

1. ✅ **无「不通过」项，可以投板。** 10 项量测里 6 项直接通过、3 项需确认、1 项非阻塞。
2. ⚠️ **需确认项 1+2 是同一个根因**：`U1`（BQ24072，VQFN 带散热焊盘）用的是 KiCad 官方
   `VQFN-16-1EP_..._ThermalVias` 封装，它把散热焊盘里的 **4 个散热过孔建模为 PTH 焊盘**
   （0.20 钻孔 / 0.50 焊盘），于是撞上「**除过孔外的插件孔最小 0.5 mm**」与「**插件孔焊环极限 0.18**」。
   就几何而言它们是散热过孔（周围全是同网络铜，没有元件引脚穿过）⇒ **按过孔判全部达标**
   （内径 0.20 = 下限、外径 0.50 ≥ 0.45、焊环 0.15 ≥ 0.0762）。
   - **答复话术（若下单被 EQ 询问）**：*「U1 的 4 个 0.2 mm 孔是散热焊盘内的散热过孔（thermal via），
     不是元件引脚孔；该封装为 KiCad 官方库标准封装，请按过孔工艺处理。」*
   - ⛔ **不建议**把它改成 0.3 mm 钻孔：该封装刻意用 0.20 小孔**抑制焊接时锡膏从孔下漏**，
     改大会让新手手焊更难（EP 是必须焊的散热焊盘）。
3. ⚠️ **需确认项 3：内层过孔到铜面间隙。** 厂家要求「内层过孔边到线路铜面/导线间隙 0.3 mm 以上」。
   本板按**过孔环边**量有 **499 处落在 0.201–0.283 mm**（主要来自键区灯珠焊盘 ↔ 平面过孔的密集处：
   GND 238 / VLED 209，配对类型 457 处为「焊盘↔过孔」）。
   但若厂家指的是**钻孔边**，则实际是 0.30 + 0.15(环宽) = **0.35–0.43 mm ⇒ 达标**。
   两种解读结论相反 ⇒ 下单时如被询问，按上一条同样口径答复；**不建议为此重布**（见 §4）。
4. ℹ️ **非阻塞项：丝印最小字符高 0.800 mm**（厂家 ≥1.0）。厂家口径是「字粗不够的加宽、
   压在焊盘上的掏掉，其它不特别处理」⇒ 偏小的字可能印不清。**键盘丝印被定位板与键帽遮挡**，
   收益极低，不改。
5. ℹ️ **丝印压焊盘 111 处 / 丝印重叠 199 处**：厂家 CAM **会自动掏空压在焊盘上的字符** ⇒
   不影响投板（这也是我们 DRC 里把 `silk_*` 整类豁免的理由，现由厂家官方口径佐证）。
6. ℹ️ **阻焊开窗**：本板 `pad_to_mask_clearance = 0`（KiCad 惯例），厂家**自动单边扩 0.05 mm** ⇒
   不需要我们改；`pad_to_mask_clearance` 保持 0 是对的。

## 3. 下单规格（建议，依据 = 板文件里的 `(stackup)` 与既有设计决定）

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 层数 / 板厚 | **4 层 / 1.6 mm** | `(general (thickness 1.6))` + `(stackup)` |
| 铜厚 | **外层 1 oz（0.035）、内层 0.5 oz（0.0152）** | 板文件 `(stackup)`；内层 0.5 oz 经瓶颈分析证明足够（见 `research/power-trace-width-precedent.md` §0.5） |

### ⚠️ 为什么不把投板产物入库

**实测：同一块板连导两次，14/14 个文件逐字节都不同** —— gerber 头部（X2 属性）与 `.gbrjob`
里带创建时间戳。入库会让本项目的硬判据「重跑生成器后 `git status` 对 tracked 文件无差异」
永远失败。因此 `.gitignore` 里忽略了 `hardware/pcb/StarShield/fab/`。

> 社区常见做法是把 gerber 一并提交（本机样本里有 235 个 zip/仓库），那是**拿确定性换便利**；
> 本仓库选确定性。要把成品给复刻者时，**把 zip 挂到 GitHub Release 附件**（不占仓库历史）。

### 复核与踩坑

- **第三方 gerber 复核**（成熟做法）：用独立查看器（KiCad Gerber Viewer / `gerbv` / 在线）
  确认外形层、槽孔、自定义焊盘渲染无误，再提交订单。
- ⚠️ **kicad-cli 用 Windows 版时不要喂 MSYS 风格路径**（`/d/StarShield/...`）——
  会报「原理图文件不存在或无法访问 / 加载原理图失败」，看着像文件坏了，其实是路径方言问题。
  脚本内部已统一用绝对 Windows 路径。
- ⚠️ 导 BOM 时 kicad-cli 会提示「原理图存在批注错误」。已逐项排查：**全工程 0 个未批注位号**
  （`Reference` 无 `?`）、BOM 共 313 件与 321 个封装（含 8 个安装孔）自洽 ⇒ **属提示误报**。

### 顺带修掉的一个可复刻性缺口

本工程原先**没有 `fp-lib-table`** ⇒ 任何人克隆后打开工程，ERC 都会报 95 条
`footprint_link_issues`（「当前配置中不包含封装库 'StarShield'」），因为自画的
MX 热插拔座封装库没有被映射。已按社区成熟写法（参考 Apollo87H 的同名文件）补上
`hardware/pcb/StarShield/fp-lib-table`，指向 `${KIPRJMOD}/footprints/StarShield.pretty`。
**复核结果：ER-C 里 `footprint_link_issues` 95 → 0。**
（符号侧用的是 KiCad 官方库 —— 74xx / Battery_Management / Connector / Device / LED /
Switch / Transistor_FET / power ⇒ 不需要 `sym-lib-table`。）

**为什么不为「内层过孔 0.3 mm」重布**（成本对照）：

| 方案 | 代价 | 收益 |
| --- | --- | --- |
| 接受现状（推荐） | 0 | 若厂家按钻孔边判 ⇒ 已达标；若按环边判 ⇒ 属其**建议值**而非绝对能力（其绝对下限 0.09），仍有 2.2× 余量 |
| 把内层 clearance 提到 0.3 并重布 | 全板重布 + 再验证（键区高密度处可能无法收敛）；此前 B4/B6-2 两轮布线成果大部分作废 | 消除该「需确认」项 |
| 只有确实被厂家退回时才做 | — | — |

## 5. 诚实边界

- 本文的厂家限值取自**嘉立创官网单一页面**（另有其官方博客交叉印证），**换厂家必须重新取值**；
  多数限值同时给出了「标准值」与「极限值」，本文对**需确认项**给出了两种解读而不是挑一个报。
- 「丝印自动掏空」「阻焊自动扩 0.05」是厂家**书面口径**，不是我们在本厂的实测；
  首次投板后应以实际成品核对。
- 「社区此封装大量投产未见退回」属**[INFERENCE]**（基于封装来源与其通用性），非统计结论。
- 表面处理建议（沉金）是**性价比判断**，不是实测数据；板文件目前未固化该项。
- 内层过孔间隙的 499 处是**用自定义 DRC 规则量出来的**（规则语法见
  `hardware/pcb/StarShield/Starshield.kicad_dru` 与 handoff §10.2 第 48 条），
  量的是过孔**环边**到其它网络铜面的距离；这是 KiCad 的 clearance 口径。
