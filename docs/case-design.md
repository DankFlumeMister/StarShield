### 1.2 坐标系（板 → 模型）—— ⚠️ 少转一处就是整片镜像

| | 方向约定 |
| --- | --- |
| KiCad 板坐标 | x **向右**、y **向下**（所以板 y=0 那条边画在屏幕**上边**） |
| Fusion 模型 | x 向右、**+Y 向上**（本脚本约定 +Y = 键盘**后侧**、远离用户那一边） |

装配关系：PCB 就是上盖、**F.Cu 朝上**；而 **KiCad 的 F.Cu 视图 = 从上往下看装好的键盘**，
KiCad 屏幕「向下」这个方向在模型里就是 −Y ⇒ **板 y 必须取反、x 不动**：

```
X_model = x_board                     （板 x 小的一侧 = 键盘左侧；模块 USB-C 从板 x=0 那面壁伸出）
Y_model = (by0 + by1) − y_board       （by0/by1 = 板框 y 的最小/最大值 = 0 / 151.0625）
```

换算**只有这一处**：脚本里 `YF()` / `YR()` / `rectY()`（模块级）。
凡是用到「板的 y」的几何（板框外扩、安装孔、侧壁开孔、电池仓压边）都必须走它们，禁止直接写裸 y。

**数值自查（板布局事实，不是假设）**

| | 板坐标 | 模型坐标 | 应落在 |
| --- | --- | --- | --- |
| 三处开孔 | y = 0 / 17.8（x = 15 / 33 / 0） | Y = 151.1 / 128.3…138.3；x = −3.3…37.0 | **上边 + 左端** |
| 8 个安装孔 | y = 60 / 110 / 149.06（x = 2 / 124.9 / 249.8 / 372.7） | Y = 91.1 / 41.1 / 2.0 | 下边与左右两端 |

⇒ 判据：`min(开孔 Y) > max(安装孔 Y)` 且 `max(开孔 x) < 板宽/2`。脚本里做成 **③b 方向自检**，不满足直接抛错。

**❌ 首版错在哪**：漏了 y 取反 ⇒ 模型在 Y 上镜像，三处开孔跑到键盘「前下边」、螺丝柱跟着镜像，
与 PCB 布局左右上下全对不上（用户一眼看出「开口应该在左上角」）。

**为什么这类错必须靠数值判据**：镜像后的几何在 DRC、在等轴截图里**都看不出对错**
（图里只是一个浅盘换个角）。所以本项目加了**两道**朝向判据，且都不依赖看图：

1. **脚本内 ③b 自检**（上面两条不等式，几何画完立刻判）；
2. **日志里的「字符俯视图」**（`draw_plan()` 用真实坐标画 ASCII：上 = +Y、左 = −X，
   `H` 安装孔 / `O` 开口 / `b` 电池仓 / `|` 分件缝）—— 不用开图就能核对；
3. 另有**离线预检** `.workbuddy/scratch/check_plan.py`：给 `adsk` 打桩，**不开 Fusion**
   就能跑通换算并打印同一张字符图（改坐标转换前先跑它，省一次 Fusion 往返）。

运行后还会多出一张 **`preview-top.png`**：相机放正上方、up = +Y ⇒ **屏幕右 = +X、屏幕上 = +Y**，
可与 KiCad 的 F.Cu 视图逐点对照（等轴图做不到这点 —— 它没有明确的正方向）。

**✅ 2026-09-21 02:31 复跑：修好并核对通过** —— ③b 方向自检 ✅，日志字符俯视图里
开口在上边 + 左端、安装孔在下边与左右两端，与上表逐点一致；体积自检 +1.76 / +12.80 cm³ 不变
（印证「镜像不改变这些量、只能靠朝向判据发现」）。

**⚠️ 一个前提假设（待你确认）**：上表把「板 x=0 那面壁 = 键盘左侧」当作事实，依据是
`sketch/keyboard-layout.json`（KLE）里键位 x 向右递增、板坐标与 KLE 同向。
若你实际想要的是「整板在壳内转 180°」（即端口在键盘**右**端），那 x 也要取反一次，
改动同样只有一处（`rectY` 里对 x 做 `bx0 + bx1 − x`），说一声即可。

## 3. 脚本能建出什么（v1 范围）

底壳（两件）+ 内腔 + **三处侧壁开孔**（做成**顶部开口的槽**：打印机友好，且不必赌连接器精确高度）
+ **8 个 M2 自攻柱与底孔** + **左右两个电池仓压边**（每条边两条压臂，压边高出电池 2 mm）。
导出：`StarShield-case.step`（整件）、`StarShield-case-A/B.stl`（分件）、
`preview-iso.png`（等轴截图）、`preview-top.png`（**俯视截图**，屏幕右 = +X、屏幕上 = +Y）。

**v1 刻意不做**（都需要先定案，见 §6）：定位板的承托与压边、上盖/边框、脚垫与倾角、
电池引线走线槽、外壳与 PCB 的防呆。

## 4. 怎么运行（**手动一步**）

Fusion 没有进程外 API —— 脚本必须在 Fusion 进程内跑，因此**只能**通过它的入口触发。

**⚠️ 两个先决条件（2026-09-21 实测踩过）**
1. **「实用程序」标签只在打开了一个设计文档时才出现** —— 停在**主页（Home）**是找不到它的。
   ⇒ 先在主页点「新建... → 零件设计 → 新建」，进入工作区后工具栏最右侧就有「实用程序」。
2. **脚本必须放在 `%APPDATA%\Autodesk\Autodesk Fusion 360\API\Scripts\<名>\`**。
   放到同级的 `MyScripts\` 里，**「脚本和加载项」对话框里看不到它**（首版就放错了）。

**步骤**
1. 打开 Fusion 360，进入任一设计（或按上面第 1 条新建一个零件设计）。
2. 工具栏最右 **实用程序（Utilities）→ 脚本和加载项（Scripts and Add-Ins）**；
   快捷键 **`Shift+S`** 更快（实测有效）。
3. 对话框里：若「搜索」框有残留文字先清掉（点 ×）；在**脚本**列表里找到 **StarShieldCase**
   → 点它那一行的 **▶（运行）**。
4. 完成后看 `hardware/case/out/build.log`（逐步日志 + 每步体积自检）与 `out/` 下的 STEP/STL/预览图。

部署/更新脚本：`python docs/_tools/deploy_fusion_addin.py`（装到 `API\Scripts\` 与 `MyScripts\` 两处；
`--remove` 卸载）。

## 5. ⚠️ 踩过的坑（Fusion 自动化事实，供后续复用）

1. **Fusion 没有进程外 API**，也没有命令行执行脚本的开关 ⇒ 想自动化只能在启动时挂钩子，
   或者模拟输入点击。**不存在** headless/batch 模式。
2. **`runOnStartup: true` 的 add-in 机制是真的**（依据：安装目录里多个内置 add-in 清单都用它，
   路径 `%APPDATA%\Autodesk\Autodesk Fusion 360\API\AddIns\<名>\<名>.manifest`）。
   实测**确实自动跑起来了**（重启后 45 秒写出日志）。
   ❗ **但不要在启动阶段做重活**：Fusion 启动初始化尚未完成时建模，会把 Fusion 跑崩
   （崩溃报告落在 `%LOCALAPPDATA%\Autodesk\CER\`）。
3. **首版脚本自身也不稳**：每个小体都新建「构造平面 + 草图 + 拉伸」，8 柱 + 8 底孔 + 24 个压边
   ⇒ 40+ 特征；且沿用了特征重建后**已失效的 body 代理**（SWIG 代理问题）。
   ⇒ 现版本改为**一次草图装多个轮廓、一个特征干一批**（总特征 ~7）+ **每步重新获取 body**。
4. **别用 `taskkill /F` 强杀 Fusion**：本机两次强杀之后，Fusion 变成**每次启动 4 秒内崩溃**
   （`SafeModeCounter.json` 记到 1，即它已记录一次启动失败）⇒ 需要用户自己启动、按提示进安全模式/清缓存恢复。
5. 本机杂项（都有证据，不是猜）：Fusion 界面截图只能用 **Pillow**（`ImageGrab`）——
   PowerShell 的 `Add-Type` 被安全策略拦；`sleep` / `tee` 等 coreutils 在 Bash 工具里不可用；
   Windows 里的 `timeout.exe` 不是 GNU timeout。
6. 🔴 **拉伸「草图里所有轮廓」会把「环内区」一起填实 —— 环形件必须按 `profileLoops` 选轮廓。**
   而且**轮廓怎么画决定 loop 数**：
   - ✅ 每个环用**两个同心矩形** ⇒ 「环带」是一个**带孔轮廓（2 个 loop）**，
     内框区域是 1 个 loop ⇒ 传 `min_loops=2` 精确取到环带。
   - ❌ 用**4 个互相重叠的矩形**拼环 ⇒ 会被切成若干**单环区域**，连「环内区」也是 1 环
     ⇒ 按 loop 数无法区分，一起拉伸就把电池仓填成实心块
     （实测体积 +108 而非 +13 cm³，`min_loops=2` 时则一个轮廓都选不到）。
7. ⚠️ **Fusion 几个「不能做 / 已废弃但可用」**（省一轮试错，均在 `API/Python/packages/adsk/fusion.py`
   这份**本机 API 存根**里核对过）：`root.name = "..."` 会抛
   `RuntimeError: 3 : root component name cannot be changed`（根组件不能改名，首次运行就崩在这行）；
   `setDistanceExtent` 官方标注已废弃但**明确说明继续兼容**（换新 API 风险更大，保持不动）；
   `participantBodies` 要的是 **`list[BRepBody]`**。**不确定签名就直接读存根，比试错快。**
8. 💡 **每步都要有数值自检。** 上面第 6 条的缺陷 **DRC 查不到、等轴视图里也看不出对错**
   （就是两块方块），是脚本自己的体积增量自检抓到的 ⇒ 生成几何的脚本务必逐步输出可判读的量。
9. 🔴 **KiCad 板坐标 → 模型坐标必须做 y 取反**（`Y_model = (by0+by1) − y_board`），
   这是本项目最容易犯、也最难靠看图发现的错（首版就漏了，见 §1.2）。
   两条纪律：① 换算**只有一处**（`YF/YR/rectY`），不得散落；
   ② 加**朝向自检** + 日志里的**字符俯视图**——等轴截图判不出正方向。
